# champions-ai

Pokémon Champions向けの対戦判断支援AIを作るTypeScriptプロジェクトです。ポケモン・技・タイプ相性などの基礎データには、Pokémon Showdownの`champions` modを利用します。

## 画面

- `http://127.0.0.1:3000/` — 1対1の旧・簡易評価画面
- `http://127.0.0.1:3000/live.html` — ポケチャン対戦中の状態追跡・現在盤面評価画面

ライブ画面では、手動入力・Showdownプロトコル・将来の画面認識が共通の`BattleEvent`を生成し、同じ`BattleStateStore`と評価器を使用します。

```text
手動入力 ─────────┐
Showdownログ ─────┼→ BattleEvent[] → BattleStateStore → CurrentBattleEvaluator
画面認識（予定） ─┘
```

## ライブ画面で登録できる情報

- 自分・相手の最大6体のチーム
- レベル、現在HP・最大HPまたはHP率
- 技、持ち物、特性、テラスタイプ、テラスタル使用状態
- HP・攻撃・防御・特攻・特防・素早さの実数値
- 場にいる左右2体と控え
- 状態異常、ひんし、全7種類の能力ランク
- 使用が判明した技
- 天候、フィールド、トリックルーム
- おいかぜ、壁、設置技などのサイド状態
- こんらん、ちょうはつ、みがわりなどの一時状態
- 各状態の継続ターンと自動終了

実数値が未入力の場合は、レベル50・個体値31・努力値0・性格補正なしの値で補完します。相手の未公開情報は不明のまま保持し、判明した情報だけを追加できます。

## 現在盤面の評価

ライブ画面の「現在盤面を評価」から、登録済みの`BattleState`を直接評価します。

現在の評価器は以下を行います。

- 各ポケモンの技と対象候補を生成
- 控えへの交代候補を生成
- 第9世代の基本ダメージ式と16段階の乱数範囲を計算
- タイプ一致、テラスタル、タイプ相性、能力ランクを反映
- 天候、フィールド、壁、全体技補正、やけどを反映
- 主要な持ち物・特性を反映
- 命中率、行動順、KO率、盤面制御、控えへの一貫性を採点
- 相手の判明済み技から最大被害を見積もり、反撃リスクとして減点
- 味方を巻き込む全体技を減点
- ダブルバトルの2体同時行動を組み合わせて採点
- 集中攻撃、片方の防御、てだすけなどの相乗効果を加点
- 得点内訳と判断理由を表示

出力される主な値は次のとおりです。

```text
ダメージ範囲
平均ダメージ率
KO確率
命中率
ダメージ得点
行動順得点
盤面制御得点
控えへの一貫性
温存価値
相手の反撃リスク
味方への被害
最終得点
```

## 精度上の制約

この評価器は実戦利用可能な初版ですが、Pokémon Showdownの`BattleStream`を用いた完全な局面探索ではありません。

- ダメージ式は第9世代の基本式に主要補正を加えたものです
- すべての技固有スクリプト、特性、持ち物は未再現です
- 相手行動は、判明済み技のうち最大ダメージとなる反撃を使った悲観評価です
- 相手の技・持ち物・特性・努力値が不明なら、その不確実性を完全には展開しません
- 交代評価は交代後の攻撃圧力・温存価値・反撃リスクによる初期版です
- 同時行動は個別得点と一部の相乗効果を合成しており、全行動組合せをシミュレーターで実行してはいません
- 複数ターン探索、選出予測、学習モデルは未実装です
- 状態は現在メモリ上にあり、サーバー再起動時に消えます

## Showdownログ取込

通常のシミュレータープロトコルに加えて、`|request|` JSONから自分のチーム、実数値、技、持ち物、特性を取り込めます。

```http
POST /api/state/showdown
Content-Type: application/json

{ "text": "|-weather|RainDance" }
```

以下のイベントも追跡します。

- チームプレビューの`|poke|`
- 交代、HP、状態異常、能力ランク
- 使用技
- 天候、フィールド、サイド状態、一時状態
- 持ち物と特性の公開・消失
- フォルム変化
- テラスタル

## API

現在状態:

```http
GET /api/state
```

手動入力または画面認識結果を反映:

```http
POST /api/state/events
Content-Type: application/json

{
  "events": [
    {
      "type": "weather",
      "condition": "rain",
      "source": "vision",
      "confidence": 0.96
    }
  ]
}
```

現在盤面を評価:

```http
POST /api/evaluate-current
Content-Type: application/json

{
  "side": "p1",
  "formatId": "gen9championsvgc2026regma"
}
```

状態を初期化:

```http
POST /api/state/reset
```

## 日本語名データ

ビルド前にPokeAPIのCSVから日本語名を取得し、Showdown内部IDとの対応表を生成します。

```bash
npm run sync:i18n
```

通常の`npm run build`でもベストエフォートで同期します。ネットワークが利用できない場合は、リポジトリ内のフォールバック辞書を使用します。Champions固有の新しい技・フォルムがPokeAPIにまだない場合は英語名を使用できます。

## 実行

Node.js 22以降を使用します。

```bash
npm install
npm run dev
```

本番相当の起動:

```bash
npm run build
npm start
```

## チェック

```bash
npm run check
```

サーバー・ブラウザーのTypeScript型検査、ビルド、旧ヒューリスティック、BattleState、Showdownプロトコル変換、現在盤面評価の単体テストを実行します。

## 構成

```text
src/
├── core/
│   ├── battle-state.ts             チームと対戦状態
│   ├── damage-service.ts           ダメージ範囲・行動順・反撃推定
│   ├── action-evaluator.ts         技・交代・同時行動の採点
│   ├── current-evaluator.ts        現在盤面評価の入口
│   └── heuristic.ts                旧・単体近似評価
├── data/                           日本語名の生成データ
├── input/                          Showdownログ・画面認識入力
├── showdown/                       Pokémon Showdownデータアダプター
├── server/                         Node.js HTTP APIと静的配信
└── web/                            ブラウザー側TypeScript
```

## 次の実装候補

1. Pokémon ShowdownのBattleStreamで、自分と相手の候補行動を実際に1ターン実行する
2. 未公開技・持ち物・特性・努力値を確率分布として扱う
3. 技固有処理と未対応の持ち物・特性を追加する
4. 対戦ログ保存、再生、評価結果との比較
5. 交代を含む複数ターン探索
6. 選出・先発予測
7. ポケチャン画面の領域切り出し、HPバー・文字・アイコン認識
8. 認識信頼度が低いイベントの確認・訂正UI
